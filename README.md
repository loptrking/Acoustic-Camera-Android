# AcousticLens

AcousticLens 是一个面向 Android 手机内置双麦克风的声源方向实验项目。它尝试在不连接外部麦克风阵列、不依赖 ARCore 的前提下，把手机相机画面、双通道音频、IMU 姿态和宽带 GCC-PHAT 时延估计组合起来，在横屏界面中显示声源相对屏幕中心的水平方向。

项目目前处于**可重复实验原型**阶段，而不是通用声学相机成品。已在一台 HONOR PTP-AN10 上确认：Android `CAMCORDER` 音源能够同时启用两颗物理麦克风；宽带时延在中心、左右两端呈稳定符号变化；60 cm 定量实验能正确感知约 ±30° 的入射变化。尚未完成的核心工作是多频段零点校准、左右非对称映射、跨环境验证和热力图式声学成像。

## 已实现能力

- 相机预览与声源方向覆盖层：用方向线、角度、置信度和宽度随不确定性变化的半透明区域展示实时结果。
- 真双物理麦克风采集：读取 `AudioRecord.getActiveMicrophones()`，记录活动麦克风、物理地址、组内索引和系统坐标。
- 宽带方向估计：在 500–8000 Hz 上执行 GCC-PHAT，并用系统报告的 14.2567 cm 麦克风间距约束最大物理时延。
- 质量门控：拒绝弱信号、相关峰不足、声道差异不足、物理越界和时间不稳定窗口。
- 稳健跟踪：对最近九个合格窗口的时延取中位数，降低瞬时反射和离群值影响。
- 姿态约束：识别横屏方向、充电口朝向、俯仰/侧倾偏差和相对偏航。
- 实验导出：保存 WAV、音频硬件时间戳、姿态序列、逐窗声学特征、设备与算法元数据，并打包为 ZIP。
- 诊断入口：提供麦克风硬件清单、路由检查、8 秒方向探针、多频段 GCC 与姿态联合诊断；诊断模式只输出聚合指标，不保存原始录音。
- 离线工具：Python 脚本可检查会话完整性、采样时钟、双声道独立性、相位/时延、姿态同步和历史标定结果。
- 可复现实验资产：仓库保留 1 kHz、4 kHz、550.78125 Hz、频点锁定多音和 500 Hz–8 kHz 宽带噪声测试文件。

## 系统数据流

```text
bottom/back 物理麦克风
          │  48 kHz stereo PCM + hardware timestamp
          ▼
    CAMCORDER AudioRecord ──► GCC-PHAT（500–8000 Hz）
                                      │
                                      ├─ 物理基线/最大时延约束
                                      ├─ 峰值比、声道差异、RMS 门控
                                      └─ 9 窗口中位数与置信度
                                                    │
Game Rotation Vector ──► 相对偏航/横屏方向 ─────────┤
                                                    ▼
CameraX preview ─────────────────────────► Compose 方向覆盖层
                                                    │
                                                    ▼
                          WAV / CSV / JSON / ZIP 实验会话
```

当前角度模型针对镜头前方半平面：

```text
azimuth = asin(clamp(-lagSamples / maxPhysicalLagSamples, -1, 1))
```

正角度表示屏幕右侧，负角度表示屏幕左侧。双麦时延本身存在前后对称性，因此“镜头前方”是当前产品约束，不代表两颗麦克风单独解决了完整 360° 方位问题。

## 开发历程与实验记录

下面的时间线对应 [`doc/progress`](doc/progress) 中 001–028 号冻结报告。每份报告记录当时的代码、测试条件和结论；后续发现不会回写旧报告，而是通过新编号保留决策演化。

### 001 — 采集骨架与音频可行性

- **完成：** 建立 Kotlin/Compose Android 工程，实现 48 kHz 单声道 PCM 采集、硬件时间戳、WAV/JSON/ZIP 导出、录制界面及 Python 分析脚本；生成 1 kHz 与 4 kHz 标准测试音。
- **发现：** 29.52 s 会话得到 1,416,960 个样本，估算采样率 47,999.686 Hz，时钟误差约 −6.55 ppm；1 kHz SNR 41.42 dB，4 kHz SNR 52.24 dB。`AudioRecord.read()` 返回节奏有抖动，不能代替硬件时间戳。
- **处理：** 后续所有音频—姿态同步以 Android 单调时钟和硬件时间戳为准；记录首段静音约 23.92 ms 的设备启动特性。
- **验证：** 采集、导出、离线频率/相位分析链路完整跑通。

完整报告：[001](doc/progress/001_M0-M1_audio_capture_and_feasibility.md)

### 002 — ARCore 失败与技术路线转向

- **完成：** 给 ARCore 检查增加异步超时和明确错误；真机返回 `UNSUPPORTED_DEVICE_NOT_CAPABLE`。
- **问题：** 主流旗舰机也可能不在 ARCore 认证列表，若把 ARCore 设为前置条件，覆盖面与项目目标冲突。
- **处理：** 删除 ARCore 硬依赖，改用 CameraX + 双麦 + IMU 原地旋转；明确不通过手机加速度二次积分估算平移，因为漂移会迅速失控。
- **验证：** 新增立体声 PCM、旋转矢量、陀螺仪、线性加速度、`orientation.csv` 和离线姿态检查。

完整报告：[002](doc/progress/002_M2_ARCore_result_and_rotation_scan_pivot.md)

### 003 — 首次双声道 + IMU 扫描

- **完成：** 采集 16.04 s 双通道音频与 808 行姿态数据，覆盖约 55.6° 偏航。
- **发现：** 两通道不是简单复制（差异比 1.245、相关峰约 0.922），时钟与 IMU 可对齐；但 4 kHz 单音每 12 个样本重复，相位/时延存在周期歧义，模型 `R²=0.036`、残差 73.5°。
- **处理：** 判定窄带整数时延不适合直接定位，下一版转向宽带 GCC-PHAT。
- **验证：** 证明采集和姿态链路有效，同时用失败数据否定单音整数时延方案。

完整报告：[003](doc/progress/003_M2R_first_stereo_IMU_experiment.md)

### 004 — 宽带 GCC-PHAT 实现

- **完成：** 实现 500–8000 Hz GCC-PHAT、±24 samples 搜索、抛物线亚采样插值、峰值比、符号约定及离线拟合。
- **处理：** 用宽带相关替代周期歧义严重的单音相关，同时保留质量分数，避免输出“总有一个角度”的假确定性结果。
- **验证：** 合成 +5 samples 延迟恢复误差小于 0.25 sample，峰值比大于 1.2；旧 4 kHz 数据仍被正确判为不可用。

### 005 — 首次宽带结果与模型边界

- **完成：** 完成 25.48 s、92.7° 的宽带旋转扫描。

### 016 — Game Rotation Vector 参考系纠正

- **问题：** 曾错误地把两个会话的 Game Rotation Vector 起始航向当作共享的绝对方位。该传感器不依赖磁北，零点可随会话变化。
- **处理：** 只在同一会话内使用相对角；设备轴偏差采用“起始镜头方向 − 声学拟合方向”，常量零点在减法中抵消，因此仍可跨会话比较。
- **验证：** 在用户确认两个实验确属不同物理方向的前提下，550.8 Hz 已满足当时的跨会话门槛。

完整报告：[016](doc/progress/016_M3_heading_frame_correction_and_550Hz_validation.md)

### 022 — PCM 与物理方向对照

- **完成：** 让充电口短边正对 20 cm 外的扬声器，再与背板正对测试比较。
- **发现：** 测得 −21.64 samples，量级与 14.2567 cm 基线对应的约 19.95 samples 最大远场时延一致；两种姿态下声道响度优势发生变化。
- **处理：** 初步建立声道/方向假设，同时保留近场、扬声器尺寸、反射和厂商处理造成偏差的解释。
- **验证：** 94 个有效窗口，峰值比 1.544，无原始环境录音落盘。

完整报告：[022](doc/progress/022_M3_pcm_channel_mapping_confirmation.md)

### 023 — TDOA 符号与对称性闭环

- **完成：** 手机原平面旋转 180°，让另一短边正对声源。
- **发现：** 两端分别约 −21.64 与 +21.88 samples，绝对值只差约 1.1%；背板正对约 +2.87 samples，形成“负—零—正”对照。
- **处理：** 固定约定：横屏充电口朝右时，负时延对应屏幕右侧，正时延对应屏幕左侧；响度差降为低权重辅助，不能简单认定 PCM 左右就是某颗物理麦。
- **验证：** 真双麦宽带 TDOA 的符号、零点和端点对称性均成立，正式终止 550 Hz 拟合物理基线路线。

完整报告：[023](doc/progress/023_M3_tdoa_sign_and_symmetry_validation.md)

### 024 — 宽带实时方向模块

- **完成：** 新增 `BroadbandDirectionTracker`，使用 14.2567 cm 固定基线、343 m/s 声速、500–8000 Hz GCC-PHAT 和前方半平面 `asin` 映射。
- **处理：** 加入弱信号、峰不足、声道差异不足、越界和不稳定拒绝；最近九窗中位数抑制离群；UI 增加方向带、方向线、角度和置信度。
- **验证：** 单元测试覆盖 ±30° 符号、物理越界和单个离群点；测试、构建、lint 全通过，发布 0.10.0。

完整报告：[024](doc/progress/024_M4_broadband_live_direction_implementation.md)

### 025 — 可机器读取的方向诊断探针

- **完成：** 将与主界面相同的方向跟踪器接入 8 s 诊断 Activity，JSON 输出方向中位数、置信度、跟踪窗口数、最终质量状态和最大物理时延。
- **处理：** 用可重复聚合数据替代仅观察 UI 动画的主观判断；诊断不保存原始音频。
- **验证：** 本地测试、构建、lint 通过；制定中心、右 30°、左 30° 的三点实验判据。

完整报告：[025](doc/progress/025_M4_direction_diagnostic_probe.md)

### 026 — 三点与多频段验证

- **完成：** 中心与目测左右约 30° 三点实验，并比较 500–1200、500–2500、500–8000 Hz 三个 GCC 频段。
- **发现：** 中心为 +0.87°；两侧结果符号相反且可重复。全频段 MAD 最低、峰值最清晰，未见高频空间混叠主导错误。
- **问题：** 测试者站在手机背面时的视觉左右与屏幕坐标左右相反；手持目测 30° 不能用于绝对误差标定。
- **处理：** 保留既有屏幕坐标符号；下一轮改用尺子和固定几何。

完整报告：[026](doc/progress/026_M4_three_point_and_multiband_validation.md)

### 027 — 纠正实验几何定义

- **问题：** 先前没有严格区分手机横向平移、绕自身偏航、绕声源公转，三者对应的声学角变化完全不同。
- **处理：** 明确定义：固定朝向横移可改变入射角；固定位置原地偏航最适合下一轮；绕声源公转且背板始终对准声源时，手机坐标中的入射角仍接近 0°，不能验证 ±30°。
- **完成：** 录制开始时把 IMU 相对航向归零，UI 显示相对转角；发布 0.10.3。
- **验证：** 测试、构建、lint 通过，并制定 `0 → +30 → 0 → −30 → 0` 连续流程。

完整报告：[027](doc/progress/027_M4_test_geometry_correction.md)

### 028 — 60 cm 定量偏航第一轮

- **完成：** 扬声器固定，手机在 60 cm 处用三脚架原地偏航，采集 0°、+30°、−30° 多个静态点。
- **发现：** 三频段中心零点不同；逐频去零后，+30° 一侧的时延增量约 +5.86 至 +6.31 samples，实时角 −27.60°，目标 −30°；另一侧增量约 −9.51 至 −11.08 samples，但全频实时角仅 +18.18°，呈明显左右不对称。
- **结论：** 真双麦能够定量感知约 ±30°，但厂商处理、麦克风方向性、机身遮挡和反射使“单零点 + 单尺度”模型不足。
- **下一步：** 对每个频段分别去零，根据峰值比、MAD 和频段一致性加权；补齐 ±30° 重复和 ±60° 数据，拟合分侧映射，并在一个连续会话中检验 `acousticAngle + relativeYaw` 是否近似常数。

完整报告：[028](doc/progress/028_M4_quantitative_60cm_first_pass.md)

## 关键技术结论

1. **不需要 ARCore 才能做水平方向实验。** 当前任务只需要手机自身坐标中的声源方位和相对旋转，IMU 足以提供连续会话内的相对偏航；它不能可靠替代视觉/测距系统进行米级平移估计。
2. **“Android 返回双声道”不等于“启用了两颗物理麦克风”。** 必须结合 `getActiveMicrophones()` 和受控方向实验验证路由。本机 `VOICE_RECOGNITION` 失败，`CAMCORDER` 才提供真实双麦基础。
3. **人耳能力不能直接由手机双麦复制。** 人耳有头部遮挡、耳廓频谱线索、神经系统先验和主动转头；手机麦克风的位置、朝向、厂商处理和系统路由都不同，需要设备实测和质量门控。
4. **失败数据是算法的一部分。** 项目没有通过放宽阈值制造成功，而是多次让 `NOT_READY` 阻止物理不一致结果，最终定位到错误音频路由。
5. **当前证明的是“方向感知可行”，不是“通用声学成像已经完成”。** 中心/左右符号、固定基线量级和一侧约 30° 精度已得到证据；跨房间、跨设备、不同频谱、多个同时声源和二维热力图仍未完成。

## 已知限制

- 目前只在一台 HONOR PTP-AN10 上进行了完整硬件诊断；不同厂商和型号可能返回不同麦克风路由，甚至无法开放真双麦 PCM。
- `CAMCORDER` 仍可能包含厂商增益、滤波、混音或降噪，不能视为完全未处理的裸麦数据。
- 两颗麦克风主要提供一维时延，天然存在前后对称；相机使用场景目前把结果约束在镜头前方半平面。
- 多径反射、近场扬声器尺寸、手机壳/手部遮挡和麦克风方向性会改变零点与灵敏度。
- 左右两侧响应不对称，当前 0.10.4 尚未把分频段零点和分侧映射接入正式实时跟踪。
- 暂不支持多个同时声源、俯仰角定位、真正二维声强热力图或跨设备统一标定。
- 当前安装包是诊断构建，不是应用商店发布版。

## 下一阶段计划

1. 在固定 60 cm 几何下补采 +30°、−30° 各两次，以及 +60°、−60° 各三次，并在每个侧向点前后插入中心点。
2. 把三个频段的 GCC 计算合并到一次 FFT，降低实时计算开销。
3. 为每个频段保存设备级中心零点，先去零再按峰值比、MAD 和跨频一致性进行鲁棒加权。
4. 分别拟合左右两侧映射，并用保留样本检查是否过拟合及是否需要非线性项。
5. 在一次连续录制内完成原地偏航，验证声学角与 IMU 相对偏航的互补关系和滞后。
6. 在第二个房间、多个距离和不同频谱声源上做盲测；通过后再进入稳定 UI、结果留影和声学覆盖层产品化。
7. 增加设备能力探测：无法确认两颗活动物理麦克风时明确降级，而不是输出伪方向。

python -m pip install -r python/requirements.txt

## 真机使用流程

1. 下载最新 APK 并安装，授予麦克风和相机权限。
2. 打开系统自动旋转，把手机横过来并保持充电口在右侧。
3. 固定手机或稳定手持，避免遮挡机身底部和背部麦克风。
4. 使用宽带、持续、信噪比较高的声源；点击开始后观察方向、置信度和质量提示。
5. 质量未达到 `TRACKING` 时不要把最后一个角度当作有效结果。
6. 结束后可导出实验 ZIP；公开反馈问题前应先检查包内是否包含真实环境录音或设备信息。

定量复现实验请按 [`doc/M4-quantitative-experiment-plan.md`](doc/M4-quantitative-experiment-plan.md) 执行；其他阶段的完整流程位于 [`doc`](doc) 目录。
