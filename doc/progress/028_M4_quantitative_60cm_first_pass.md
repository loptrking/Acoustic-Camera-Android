# 028 M4 60 cm 定量偏航第一轮

日期：2026-09-26  
版本：0.10.4  
状态：第一轮 0°/±30° 定量实验完成

## 隐私边界

本轮仅启动 AcousticLens 诊断入口、播放项目内测试噪声，并读取本应用私有目录中的聚合 JSON。所有结果均为 `raw_audio_saved: false`，没有访问手机其他文件或应用。

## 实验条件

- 电脑扬声器固定不动。
- 手机与扬声器距离 60 cm。
- 手机固定在三脚架上，横屏且充电口位于屏幕右侧。
- 通过尺子坐标设置手机原地偏航；扬声器和手机转轴均不平移。
- 每点播放 500 Hz–8 kHz 宽带噪声约 10 秒，诊断采集约 8 秒。

## 姿态质量

调平后各有效点的横滚约为 −89.15° 至 −89.41°，俯仰约为 +0.38° 至 +0.76°，静态角速度为 0，满足定量实验姿态要求。

## 中心零点

取四次调平后的 0°会话中位数，三个频段的零点分别为：

- 全频 500–8000 Hz：`+3.23 samples`
- 低频 500–1200 Hz：`−2.75 samples`
- 中频 500–2500 Hz：`−0.28 samples`

未校正时，全频实时角在中心位置约偏向 −6°至 −14°。不同频段的中心偏置方向不同，说明单一全频零点不能代表设备的全部传输特性。

## 几何 +30°：声源相对手机 −30°

减去各频段中心零点后的时延增量：

- 全频：`+5.95 samples`
- 低频：`+6.31 samples`
- 中频：`+5.86 samples`

三个频段校正后高度一致。当前全频实时角为 `−27.60°`，目标为 `−30°`，误差约 2.4°。

## 几何 −30°：声源相对手机 +30°

减去各频段中心零点后的时延增量：

- 全频：`−9.51 samples`
- 低频：`−9.71 samples`
- 中频：`−11.08 samples`

三个频段方向一致，校正后仍较接近。当前只使用全频的实时角为 `+18.18°`；低频和中频单独换算约为 +38.7°与 +34.7°，说明这一侧需要分频段校准融合。

## 关键发现

1. 左右符号与声源方向均正确，单手机真双麦能够定量感知约 ±30°入射变化。
2. 每个频段存在不同的固定零点；减去各自零点后，同一方向的三个频段增量明显收敛。
3. 两侧灵敏度不对称。按单个 30°样本估算，正时延侧的有效尺度约 12 samples，负时延侧约 20 samples。该差异可能来自厂商 `CAMCORDER` 处理、麦克风方向性、机身遮挡和房间反射。
4. 每侧目前只有一个正式 ±30°样本，不能把上述不对称尺度直接写入正式算法，否则会过拟合。
5. 简单地固定使用全频、固定使用低频或直接取三个原始时延的中位数都不是最终方案。正确方向是先做每频段零点校正，再进行可靠性加权融合和分侧映射。

## IMU说明

诊断 Activity 在每个静态点重新注册 `TYPE_GAME_ROTATION_VECTOR`。该传感器不使用地磁场，参考 Y 轴不指向磁北，参考方向允许随陀螺仪漂移。因此不同独立诊断会话的绝对航向不应直接相减。

正式 App 在一次连续录制内建立起点并计算相对旋转，这仍是正确方法。下一轮动态实验必须使用同一个连续会话，不再用多个静态诊断 JSON 的绝对航向比较转角。

参考：Android Developers，Position sensors / Game rotation vector sensor：
https://developer.android.com/develop/sensors-and-location/sensors/sensors_position

## 下一算法结构

1. 一次 FFT 前向变换同时计算低频、中频和全频 GCC-PHAT，避免当前诊断版重复执行三次完整 FFT。
2. 为每个频段保存设备级零点偏置。
3. 将各频段转换为去零点后的时延增量。
4. 根据峰值比、MAD和频段间一致性进行鲁棒加权融合。
5. 使用至少三个角度和每角度三次重复结果拟合左右两侧映射，不以单个 ±30°样本决定比例。
6. 连续录制中用 IMU 相对转角校验 `acousticAngle + relativeYaw` 是否保持常数。

## 下一轮最小实验

- 重复几何 +30°两次；
- 重复几何 −30°两次；
- 新增几何 +60°与 −60°各三次；
- 每次前后插入 0°中心点。

完成后即可拟合带零点、左右分侧尺度和非线性检查的设备校准曲线。
