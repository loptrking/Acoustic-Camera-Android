# 开发进程报告 001：项目基线、音频采集与相位可行性

日期：2026-09-19  
覆盖阶段：Milestone 0 至 Milestone 1 音频部分  
状态：已完成并冻结

## 本阶段目标

建立 AcousticLens 的项目基线与第一条真实数据链路，确认普通 Android 手机能否稳定采集带硬件时间戳的 PCM 音频，并验证跨时间相位是否足以支持后续合成孔径实验。

## 已完成开发

1. 建立核心 PRD，明确产品边界、数据格式、阶段目标、评价指标和技术风险。
2. 创建 Kotlin 与 Jetpack Compose Android 工程。
3. 实现 48 kHz、单声道、16-bit PCM 的 AudioRecord 采集。
4. 设备支持时选择 UNPROCESSED，否则使用 VOICE_RECOGNITION。
5. 保存标准 WAV、逐块音频时间戳 CSV 和设备元数据 JSON。
6. 实现 session ZIP 导出。
7. 建立深色声学仪表盘界面、实时 RMS 电平动画、录制计时和状态反馈。
8. 建立 Python session 读取、自动质量检查、测试音生成和稳定音相位分析工具。
9. 生成 1 kHz 与 4 kHz、30 秒、−12 dBFS 的相位连续测试音。

## 实验一：普通环境录音链路

设备为 HONOR PTP-AN10，Android 17。录音时长 29.52 秒，共 1,416,960 个样本。

结果：

- WAV 数据区大小与样本数完全一致。
- App 写入的音频帧连续。
- 692 条 Android 音频管线时间戳全部有效。
- 音频帧位置和时间戳均无倒退。
- 由硬件帧位置与单调时钟估算的实际采样率为 47,999.686 Hz。
- 采样率误差约 −6.55 ppm。
- 软件读取结束时间相对硬件音频时间戳存在约 −17.1 至 +21.3 ms 的变化，因此不能用 read 返回时间替代硬件时间戳。
- 启动阶段有约 23.92 ms 零值，之后没有发现中途数据中断。
- 削波样本 22 个，占 0.00155%，不影响链路验证。

结论：录音、时间戳、WAV 保存和 ZIP 导出链路通过。

## 实验二：1 kHz 稳定音

录音时长 15.04 秒，稳定音段约 15.02 秒。

结果：

- 估计频率：1000.010390 Hz。
- 中位幅度：−53.65 dBFS。
- 幅度标准差：2.49 dB。
- 近似信噪比：41.42 dB。
- 相位残差标准差：10.29°。
- 相邻窗口最大相位跳变：6.14°。
- 相干性：0.9841。
- 等效路径误差：9.81 mm RMS。
- 近似 THD：1.41%。

结论：跨时间相位质量良好。

## 实验三：4 kHz 稳定音

录音时长 14.96 秒，稳定音段约 13.40 秒。

结果：

- 估计频率：4000.013587 Hz。
- 中位幅度：−54.72 dBFS。
- 幅度标准差：1.53 dB。
- 近似信噪比：52.24 dB。
- 相位残差标准差：23.57°。
- 相邻窗口最大相位跳变：11.65°。
- 相干性：0.9202。
- 等效路径误差：5.61 mm RMS。
- 近似 THD：6.25%。

结论：4 kHz 相位抖动高于 1 kHz，但等效空间误差更小，可用于第一轮合成孔径原型。较高谐波失真是播放设备、房间、手机麦克风及系统处理共同形成的端到端结果，不能单独归因于手机。

## 阶段决策

纯手机合成孔径路线通过音频可行性门槛，项目进入位姿采集与同步阶段。后续使用 4 kHz 稳定音进行 20–30 cm 孔径扫描。每次实验必须从录音估计实际载波频率，不能将载波硬编码为恰好 4000 Hz。

下一阶段需要记录 ARCore 位姿、追踪状态、相机帧时间戳和 System.nanoTime 单调时钟，并将音频帧时间映射到同一时间轴。

## 已知限制

- 当前设备使用 VOICE_RECOGNITION 音频源，AGC、降噪和厂商处理状态仍未独立确认。
- 稳定音测试只覆盖约 15 秒，足以完成初步相位判断，但后续扫描实验仍需单独验证。
- 4 kHz 的相位质量只能支持原型，不代表已达到测量仪器精度。
- 当前尚未采集相机位姿，无法进行真实空间重建。
