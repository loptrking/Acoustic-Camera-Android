# 开发进程报告 002：ARCore 兼容性结果与旋转扫描路线切换

日期：2026-09-19  
覆盖阶段：Milestone 2 位姿方案验证与 M2R 采集实现  
状态：已完成并冻结；真机验证结果进入下一编号报告

## 本阶段目标

验证 ARCore 能否作为纯手机声学成像的通用位姿来源；在目标设备不支持时，重新建立不依赖外部硬件、ARCore 或场景三维重建的技术路线。

## 已完成实验与结果

目标设备为 HONOR PTP-AN10。最初版本调用同步 ARCore 支持检查，设备长期停留在“正在检查 ARCore 支持”。修复版改用异步检查、10 秒超时和 CameraX 普通相机降级后，设备返回：

`UNSUPPORTED_DEVICE_NOT_CAPABLE / 设备未通过 ARCore 支持认证`

Google 官方设备清单未列出 HONOR Magic7 Pro/PTP-AN10。该结果说明 ARCore 的支持取决于具体型号、SKU、系统镜像和设备配置文件认证，而不是手机算力是否足够。继续将 ARCore 作为核心依赖会使中国市场的设备兼容性不可控。

## 阶段技术决策

1. ARCore 从主运行链路中移除。
2. 不再以手机平移轨迹和合成孔径作为首要实现。
3. 改为“内置双通道音频 + IMU 姿态 + 原地旋转扫描”的方向定位路线。
4. Rotation Vector 用于获取手机朝向；陀螺仪用于角速度和扫描质量；线性加速度用于检测过大平移。
5. IMU 不用于积分平移距离。惯性传感器仅能较稳定地提供短时姿态，无法独立提供厘米级平移。
6. 当前路线的第一门槛是设备是否暴露两个真正独立、同步的输入声道，而不是立刻生成热力图。

## 已完成开发

- CameraX 普通预览取代 ARCore 相机预览。
- 移除 ARCore Manifest 声明、运行检查和依赖。
- AudioRecord 优先请求 48 kHz、16-bit、立体声 PCM，不支持时自动回退单声道。
- WAV、时间戳和元数据按实际通道数写入。
- 实时计算整数采样时延、互相关峰值和归一化通道差异。
- 新增纯 Kotlin 时延估计器及已知 5-sample 延迟单元测试。
- 新增 Rotation Vector、Gyroscope 和 Linear Acceleration 同步采集。
- 新增 `orientation.csv`，保存传感器时间戳、回调单调时钟、四元数、欧拉角、角覆盖、角速度和线性加速度。
- 界面改为显示相机画面、方位/俯仰/横滚、60° 扫描覆盖、通道数、时延、相关度和通道差异。
- 新增离线工具 `python/analyze_rotation_scan_session.py`。
- 核心 PRD 更新为 v0.2 旋转扫描路线。

## 软件验证结果

- 已知右声道延迟 5 samples 的合成单元测试通过，算法恢复 5 samples，峰值相关度大于 0.99。
- Android M2R APK 构建成功。
- Android Lint 完成，无阻断错误。
- ARCore 已不再出现在 APK 的运行依赖和 Manifest 中。

## 尚未得到的实验结论

本阶段尚无权宣称手机可以完成声源方向定位。必须先取得下一次真机录音，回答：

1. PTP-AN10 是否接受 `CHANNEL_IN_STEREO` 并返回两个声道；
2. 两声道是否为同一信号复制；
3. 左右旋转时估计时延是否产生可重复变化；
4. IMU 方位覆盖和时间戳是否连续；
5. 音频块时间与传感器时间能否映射到同一 MONOTONIC 时基。

若设备只返回单声道或复制声道，双麦旋转定位路线在该设备上不成立。项目必须如实记录该失败条件，再评估单麦克风指向性扫描；不得用虚构热图掩盖硬件限制。

## 下一步验收

按照 `doc/M2R-rotation-scan-test-guide.md` 完成约 30 秒的 4 kHz 左右旋转扫描，导出 ZIP 到 `result`。使用离线工具给出通道独立性、时延范围、姿态采样率和角覆盖报告后，才能决定是否进入方向似然算法开发。
