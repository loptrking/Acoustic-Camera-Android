# 开发进程报告 003：首次双通道与 IMU 旋转扫描实验

日期：2026-09-19  
输入会话：`result/AcousticLens_IMU_2026-09-19_143950_734.zip`  
状态：已完成并冻结

## 实验目的

验证 HONOR PTP-AN10 是否向 Android App 提供两个真正不同的同步输入声道，并验证 Rotation Vector 能否在录音期间提供连续的旋转姿态。只有这两项同时成立，纯手机旋转扫描方向定位才值得继续。

## 采集结果

- 录音时长：16.04 s。
- 格式：48 kHz、16-bit PCM、2 channels。
- 音频源：`VOICE_RECOGNITION`。
- 音频帧数：769,920。
- 削波样本：0。
- 主频：3999.939 Hz。
- Android 音频硬件时间戳完整且单调。
- 全局时钟拟合采样率：47,999.833 Hz。
- 音频时钟拟合残差 p95：0.569 ms。

## 双通道独立性

- 两声道归一化差异中位数：1.245。
- 允许时移后的互相关峰值中位数：0.922。
- 复制声道判定：否。

结论：该设备确实暴露了两个不同的同步声道，不是简单的单声道复制。纯手机双麦克风路线跨过了第一项硬件门槛。

## 姿态结果

- Rotation Vector：`Game Rotation Vector Non-wakeup`。
- 姿态行数：808。
- 覆盖时长：16.184 s。
- 姿态采样率中位数：49.865 Hz。
- 方位角覆盖：55.619°。
- SensorEvent 时间戳与回调单调时钟的相对偏移 p95 波动：9.498 ms。

SensorEvent.timestamp 与 System.nanoTime 在该设备上存在约 107.7 s 的固定时基偏移，符合 BOOTTIME 与 MONOTONIC 可能不同的现象。分析时不解释该绝对偏移，而使用记录的 `callback_monotonic_ns` 与音频 MONOTONIC 时间对齐。

结论：姿态覆盖达到本轮约 60° 的目标，采样连续，可用于后续音频—姿态融合。

## 4 kHz 时延与姿态耦合

- 普通互相关最优时延范围：−24 至 +24 samples。
- 4 kHz 在 48 kHz 下每周期仅 12 samples，因此这些峰值含明显周期歧义，不能解释为真实传播时延。
- 解包裹相位跨度：6.886 rad，等效时延跨度约 13.152 samples。
- 相位与方位角 Pearson 相关：0.186。
- 简单正弦姿态模型 R²：0.036。
- 循环相位姿态模型一致性：0.483。
- 循环模型相位残差 RMS：73.495°。

模型曾给出约 13.9 cm 的“有效基线”拟合，但由于一致性低、残差大，该数值不能作为麦克风间距或标定结果使用。

结论：本次数据尚不能从相位稳定反推出声源方向。失败不来自单声道或 IMU 缺失，而主要来自 4 kHz 单频的周期歧义、房间多径、手机机身遮挡以及 `VOICE_RECOGNITION` 厂商处理的组合影响。

## 阶段判断

旋转扫描路线可以继续，因为两个最基础的硬件条件已经满足：独立双声道和连续姿态。但下一轮不能继续把 4 kHz 单频普通互相关作为主要 TDOA 方法。

下一实验应使用 500 Hz–8 kHz 的带限宽带噪声或可重复扫频信号，并使用 GCC-PHAT 获得不依赖单一周期的时延峰。实验需要更慢地完成左—右—左往返扫描，并检验同一方位角在去程和回程得到的时延是否一致。

若宽带 GCC-PHAT 时延能够随方位角形成稳定、可重复曲线，则进入设备双麦基线经验标定和方向似然算法；若仍不稳定，则说明系统音频处理或麦克风路由破坏了可用的空间信息，纯手机方向定位路线需要重新评估。
