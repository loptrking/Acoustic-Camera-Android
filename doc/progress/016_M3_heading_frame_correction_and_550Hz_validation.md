日期：2026-09-19

## 口径修正

项目当前优先使用 Android `TYPE_GAME_ROTATION_VECTOR`。该传感器不使用地磁北作为航向零点，其水平角位于系统维护的任意参考系中，并可能随传感器会话变化或缓慢漂移。

因此，报告015中根据起始镜头角+56.85°和+90.37°推断两次实际布置只相差33.52°是不严谨的。用户已明确说明1和2是两个不同物理方向，应以实验布置记录为准，不能把 Game Rotation Vector数值解释成绝对罗盘方位。

## 为什么设备轴偏差仍可跨会话比较

每次会话的设备轴偏差定义为：

`起始镜头方向 − 声学拟合方向`

两项均处于同一传感器参考系。若该参考系存在任意常量零点偏移，减法会将其消除。因此跨会话比较轴偏差仍然成立，不要求两个会话共享磁北零点。

## 修正后的550 Hz结论

- 会话1轴偏差约−72.65°，有效基线11.60 cm，残差1.82°；
- 会话2轴偏差约−80.63°，有效基线12.05 cm，残差2.44°；
- 轴偏差差约7.98°；
- 有效基线相对差约3.8%；
- 两次一致性分数均约0.999。

在用户确认两个会话属于不同物理方向的前提下，550.78125 Hz已经满足当前跨会话认证门槛，不需要仅因姿态CSV中的起始角差值再补第三次相同标定。

## 下一开发方向

当前 App的会话状态仍由跨频率聚类决定，所以方向1显示 `CANDIDATE`、方向2显示 `NOT_READY`。这与550 Hz已经跨会话稳定并不矛盾，而是说明认证粒度设置错误。

下一版应改为：

1. 每个频率独立保存候选参数；
2. 使用相同频率跨会话比较轴偏差、有效基线和残差；
3. 550.78125 Hz优先作为首个认证频率；
4. 其他频率分别认证，不能要求它们与550 Hz共享有效基线或轴参数；
5. 普通定位首先限定为包含已认证频率的稳定声源，不宣称宽带通用定位。
