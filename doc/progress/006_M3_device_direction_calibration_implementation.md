# 开发进程报告 006：设备方向标定模块实现

日期：2026-09-19  
覆盖阶段：M3 摄像头前向与有效双麦基线标定  
状态：已完成并冻结；真机标定结果进入下一编号报告

## 开发依据

首次宽带实验中，约 543 Hz 和 996 Hz 两个独立频段分别达到 0.986 和 0.980 的循环一致性，并给出约 −148°/−147°的相同方向参数，证明双声道保留了空间相位信息。但该参数混合了声源方向、麦克风基线轴向和旧 Euler yaw 坐标偏置，不能直接投影到相机画面。

## 已完成开发

1. 新增摄像头前向角计算器。
2. 从 Rotation Vector 的设备到世界旋转矩阵中提取后置摄像头 `−Z` 光轴，并计算其水平投影方向。
3. 当镜头接近垂直向上或向下、水平投影过小时，将镜头方向判为无效，避免奇异角度。
4. `orientation.csv` 新增 `camera_heading_deg`、`camera_forward_horizontal_norm` 和 `camera_heading_span_deg`。
5. App 界面改为显示镜头前向角；扫描覆盖改由镜头方向累计。
6. 实时 FFT 新增 550、700、850、1000、1150 Hz 五个目标频段的双通道互谱相位和幅度。
7. 新增 `acoustic_features.csv`，以音频中心帧编号记录 GCC-PHAT、峰值比、通道差异和多频段相位。
8. 导出 ZIP 加入 `acoustic_features.csv`。
9. 新增 `calibrate_device_direction.py`，使用音频硬件时间戳把声学特征对齐到摄像头前向角。
10. 标定工具对每个频段拟合循环相位模型，按一致性、残差和方向聚类自动筛选可靠频段。
11. 假定录音开始时声源位于准星正中央，由此计算摄像头—麦克风基线轴向偏置和有效基线。
12. 更新旋转扫描分析工具，使新会话优先使用 `camera_heading_deg`，旧会话继续回退到 `yaw_deg`。

## 软件验证

- Android 摄像头前向计算测试覆盖正北、正东和镜头垂直奇异情况。
- Android GCC-PHAT 已知 +5 samples 延迟测试继续通过。
- Python 合成标定测试使用 5.5 cm 有效基线和 −25°方向，恢复误差小于网格分辨率；一致性大于 0.999，残差小于 1°。
- Python 文件通过语法编译和 unittest。

## 验收边界

本阶段只建立设备标定数据链路，不宣称已经得到真实设备外参。必须使用 0.4.0 APK 完成一次“声源正前方”的宽带往返扫描，并由标定工具输出 `PASS`，才能将参数用于后续左、中、右方向验证。
