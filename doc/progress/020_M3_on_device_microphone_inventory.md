# 020 M3 真机麦克风硬件清单

日期：2026-09-26

## 隐私与操作边界

本轮只对包名 `com.example.acoustic_camera` 执行覆盖安装、内部诊断入口调用，以及读取该应用私有目录中的 `microphone_inventory.json`。没有录音、没有打开相机、没有访问共享存储，也没有读取或修改其他应用与个人文件。

## 设备与版本

- 设备：HONOR PTP-AN10
- Android：17（API 37）
- AcousticLens：0.8.1（versionCode 11）
- 系统音频采样率属性：48 kHz
- 缓冲帧属性：192
- `AudioSource.UNPROCESSED` 支持：否

## Android API 返回的物理麦克风

系统向第三方应用公开两颗位于机身主体的内置麦克风：

1. `bottom`：坐标 `(0.0269, 0.0058, 0.0079)` m，朝向 `(0, 0, 1)`，方向性代码 1。
2. `back`：坐标 `(0.0546, 0.1456, 0.00415)` m，朝向 `(0, 1, 0)`，方向性代码 3。

根据系统报告坐标计算，两颗麦克风中心距离为 `14.2567 cm`。它们属于同一物理组，组内索引分别为 0 和 1。

系统还返回电话与其他虚拟输入端点，但没有坐标和物理组信息，不能作为额外的独立机身麦克风使用。因此本机对第三方应用可用的物理阵列应按两麦处理，而不是三麦。

## 对算法路线的意义

- 14.26 cm 基线足以进行水平面双麦到达时间差估计，横屏并让充电口朝右的设计方向合理。
- 两颗麦克风的位置、朝向和方向性不对称，可将频段响度差作为前后判别辅助线索。
- 系统不支持未处理音源，说明厂商音频链路可能包含增益、滤波或降噪；不能假定两通道是理想且完全同响应的裸麦数据。
- 两麦几何结构本身仍存在前后歧义，需要结合手机转动产生的动态时延/响度变化和 IMU 航向信息消歧。
- 当前 550.8 Hz 单频拟合只利用了很少的信息。后续主路线应调整为宽带多频 GCC、频段响度差、相干度和随旋转变化的概率累积。

## 下一步实验

下一步应增加一个受控的短时双通道路由测试：在用户明确同意并准备好测试声源后，只录制 AcousticLens 会话目录中的数秒测试音，调用 `AudioRecord.getActiveMicrophones()` 确认立体声通道实际映射到 `bottom` 与 `back`。该测试涉及真实录音，本轮未自动执行。
