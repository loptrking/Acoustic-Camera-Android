# 开发进程报告 018：v0.7 首次550 Hz单频门槛失败

日期：2026-09-21  
输入会话：`result/AcousticLens_IMU_2026-09-21_181607_434.zip`  
状态：已完成并冻结

## App判定

状态：`NOT_READY`，拒绝原因：`BASELINE_OUT_OF_RANGE`。

550.78125 Hz结果：

- 一致性分数：0.99686；
- 相位残差：4.54°；
- 有效基线：19.90 cm；
- 轴偏差：−34.85°；
- 角覆盖：81.34°。

分数、残差和角覆盖均满足单频质量门槛，但有效基线超过2–18 cm接受范围，因此没有保存550 Hz候选。

离线复算得到19.63 cm、−35.35°、4.56°，与手机端一致，说明不是Android实现误差。

## 为什么不能放宽基线上限

历史确定性多音会话的550 Hz结果为：

- `1.zip`：轴偏差约−72.65°，基线11.60 cm；
- `2.zip`：轴偏差约−80.63°，基线12.05 cm。

本轮轴偏差与两次历史结果相差约38°至46°，基线增至约19.9 cm。即使把18 cm上限放宽，本轮也无法满足跨会话轴偏差不超过10°、基线相对差不超过30%的认证要求。当前拒绝正确。

## 音频条件

- 左右通道RMS：0.01223、0.01556；
- 左右峰值：0.0840、0.0584；
- 无削波；
- 双通道相关系数中位数：0.853；
- 未发现复制声道。

本轮电平比`1.zip/2.zip`低约4–6 dB，但550 Hz一致性和残差仍很好，低电平不是唯一失败原因。

## 姿态差异

两次历史成功会话的横滚角非常稳定：

- `1.zip`：−67.57°至−66.61°，范围约0.96°；
- `2.zip`：−66.81°至−66.24°，范围约0.57°。

本轮横滚角为−83.35°至−72.94°，范围约10.41°；俯仰角范围约7.48°，平均线性加速度也约为历史成功会话的三倍。七阶段引导完成了水平角和回零，但扫描过程中手机平面姿态明显更不稳定。

当前模型按水平单自由度旋转拟合。横滚和俯仰变化会改变真实麦克风基线在声源方向上的投影，并与房间反射共同造成有效基线和轴偏差漂移。现有引导只限制横屏方向和端点静止，没有约束扫描过程中的横滚/俯仰保持，这是新的交互与质量控制缺口。

## 其他频率

855.5 Hz和996.1 Hz本轮分别满足单频候选质量门槛，说明多音播放和双通道采集链路仍在工作；只是首要认证频率550.8 Hz没有得到可接受的设备参数。

## 下一步

不应放宽550 Hz基线上限。下一版应增加扫描平面锁定：以开始时的横滚和俯仰为参考，实时显示偏差；偏差超过约3°时暂停引导，超过约5°持续一定时间时判定本次无效。完成该修正后再重复550 Hz双次认证，以区分姿态平面变化与音频路由长期不稳定。
