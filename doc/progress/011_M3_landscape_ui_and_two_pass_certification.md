# 开发进程报告 011：横屏界面与双次设备认证

日期：2026-09-19  
版本：AcousticLens v0.6.0  
状态：实现完成，等待真机验证并冻结

## 背景

两次横屏实验表明水平可观测性明显优于竖屏，但也暴露出旧规则只聚类方向、不约束有效基线，并允许单次会话直接激活设备档案的问题。

## 横屏产品形态

1. 新增横屏双栏工作区：左侧为相机、方向要求和角度轨道，右侧为初始化步骤、扫描指标、音频状态、结果和操作按钮。
2. 使用旋转矢量给出的横滚角识别物理方向。根据本机实测，正确方向为横滚约 −90°，即手机顶部朝左、充电口朝右。
3. 必须同时满足 Android 界面处于横屏和物理方向正确，开始按钮才可用。
4. 竖屏保留完整说明界面，但禁止开始采集；反向横屏显示翻转提示并禁止采集。
5. 采集中若设备方向离开允许范围，App 自动停止并保存会话，防止错误姿态污染设备档案。
6. 未锁死系统方向，继续遵守用户的 Android 自动旋转设置。

## 标定认证修正

1. 频段聚类现在同时要求拟合方向差不超过 25°、有效基线比不超过 1.75。
2. 小于等于 0.5 cm或大于等于 19.5 cm的搜索边界解被排除。
3. 会话有效基线接受范围收紧为 2–18 cm。
4. 单次合格结果状态改为 `CANDIDATE`，保存为待复核档案，不生成正式活动档案。
5. 第二次独立会话只有在轴偏差差值不超过 10°且有效基线相对差不超过 30%时，才升级为 `PASS`。
6. 正式档案格式升级到 version 2，并记录认证次数和复核会话。旧版 version 1 单次 `PASS` 自动失效。
7. Python 离线参考工具同步加入方向—基线联合聚类、边界剔除和 `CANDIDATE` 状态。

## 对历史横屏结果的回归

- 历史横屏测试 1 从旧规则 `PASS` 降为 `NOT_READY`：原先方向相近的两个频段基线为约 1.6 cm和11.0 cm，物理上不一致。
- 历史横屏测试 2 从旧规则 `PASS` 降为 `CANDIDATE`：剔除20 cm边界解后，855.5 Hz与1148.4 Hz形成基线和方向均可接受的候选簇，候选轴偏差约 −93.73°、有效基线约9.88 cm。
