# M3 FFT 频点锁定多音测试流程

测试文件：`doc/test_multitone_fft_bins_550-1148Hz_40s_-12dBFS.wav`

SHA-256：`9D26B555A40A997EDE805A0184EEAD55F9506958CB0203D25B14A0658717F95B`

## 信号内容

文件为40秒、48 kHz、16-bit、单声道确定性多音信号，只包含 App 当前分析的五个4096点 FFT 整数频点：

- 550.78125 Hz；
- 703.125 Hz；
- 855.46875 Hz；
- 996.09375 Hz；
- 1148.4375 Hz。

五个频点能量相等，合成峰值为−12 dBFS。与500 Hz–8 kHz宽带噪声相比，它将播放能量集中到实际分析频点，用于区分单频信噪比不足与手机音频链路的真实频率依赖。

## 播放准备

1. 将文件复制到另一部手机、电脑或扬声器播放设备，不要使用测试手机自身播放。
2. 优先使用播放设备自身扬声器或有线扬声器，不使用蓝牙音箱。
3. 关闭播放设备上的空间音频、杜比音效、均衡器和音量标准化；无法关闭时记录这一点。
4. 播放音量先设为约60%–75%。声音应清晰且不出现破音。
5. 扬声器和测试手机镜头保持近似同一高度，距离0.5–0.8 m。
6. 测试环境保持安静，手机附近不要有桌面、墙角或大型反射物；手机不要平放在桌上。

## 会话 A

1. 开启 Android 自动旋转。
2. 测试手机保持横屏：顶部/听筒朝左，充电口朝右。
3. 将扬声器置于镜头正前方，准星对准扬声器。
4. 开始播放多音文件，在5秒内点击“开始引导初始化”。不要循环播放；40秒足够完成一次引导。
5. 按屏幕完成中央、左侧、右侧、返回中央流程。转动时保持手机中心位置不平移，也不要改变横滚角。
6. 无论最终显示 `CANDIDATE` 还是 `NOT_READY`，都导出 ZIP到 `result`。
7. 记录最终提示以及播放设备音量百分比。

## 会话 B

1. 将手机和扬声器的整套布置在水平面内换到另一个绝对方向，建议与会话A相差约90°至180°。
2. 保持手机—扬声器距离、相对高度、播放音量和充电口方向不变。
3. 从文件开头重新播放，在5秒内开始第二次引导。
4. 完成后导出第二个 ZIP到 `result`，并记录最终提示。

## 注意

- 两次都必须使用同一个多音文件，不能混用旧宽带噪声。
- App v0.6仍会检查跨频率共享基线，因此可能继续显示 `NOT_READY`。本实验还会离线比较每个固定频率在两次会话中的轴偏差和有效响应。
- 若某个频率在两个绝对方向下能保持轴偏差接近，即使不同频率之间基线不同，也可以评估按频率保存经验设备参数的路线。
- 若同一频率跨会话仍明显漂移，则终止该手机内置双通道定位路线。
