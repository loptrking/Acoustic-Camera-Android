# M2R 旋转扫描可行性测试

本轮只回答两个问题：手机是否提供两个真正不同的同步音频通道，以及 IMU 姿态能否与录音同时稳定记录。当前版本尚不输出声源热图。

## 安装

安装 `release/AcousticLens-v0.3.0-rotation-scan.apk`。它可以覆盖旧版本；版本号为 0.3.0。

## 测试环境

- 将另一台设备或扬声器放在手机前方约 1 米处。
- 播放 `doc/test_tone_4kHz_30s_-12dBFS.wav`，音量保持中等，避免手机输入削波。
- 手持手机，尽量让手机位置不变，只绕竖直方向缓慢旋转。

## 操作

1. 打开 App，确认能看到相机画面和方位、俯仰、横滚角。
2. 点击“开始同步采集”。
3. 先静止 3 秒。
4. 用约 10 秒从正前方缓慢转向左侧约 30°。
5. 用约 10 秒转向右侧约 30°。
6. 回到正前方并静止 3 秒，然后停止。
7. 记录界面显示的是 `1 ch` 还是 `2 ch`。
8. 如果是 2 ch，同时记录“通道时延、相关度、差异”是否会随旋转变化。
9. 导出 ZIP，放入项目 `result` 文件夹。

## 电脑分析

```powershell
python .\python\analyze_rotation_scan_session.py .\result\你的文件.zip
```

重点判断：

- `channels` 必须等于 2，才能继续双麦旋转定位路线。
- `duplicate_channels_suspected=true` 表示两个声道很可能只是同一信号的复制。
- `lag_min_samples` 与 `lag_max_samples` 若随左右旋转出现变化，说明存在可利用的空间时延信息。
- `yaw_span_deg` 建议达到 50° 以上。
- `orientation.row_count`、采样率和回调延迟用于判断 IMU 记录是否连续。

如果设备只返回单声道，这不是操作失败，而是本轮最重要的兼容性结论；下一步需要转向“单麦克风指向性/遮挡扫描”或证明纯手机定位目标在该设备上不可实现。
